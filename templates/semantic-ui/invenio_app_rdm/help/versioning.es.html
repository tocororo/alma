Versionado de DOI

¿Qué es el versionado de DOI?

El versionado de DOI te permite:

  • editar/actualizar los archivos de un registro después de su publicación.
  • citar una versión específica de un registro.
  • citar todas las versiones de un registro.

¿Cómo funciona el versionado de DOI?

Cuando publicas una carga por primera vez, registramos dos DOI:

  • un DOI que representa la versión específica de tu registro.
  • un DOI que representa todas las versiones de tu registro.

Posteriormente, registramos un DOI para cada nueva versión de tu carga.

Esto se ilustra mejor con un ejemplo de un paquete de software. Si el software ha sido lanzado en dos versiones (v1.0 y v1.1), entonces se habrían registrado los siguientes DOI:

  • v1.0 (versión específica): 10.1234/7s0da-05p39
  • v1.1 (versión específica): 10.1234/chc5z-w0r30
  • Concepto (todas las versiones): 10.1234/3s67k-pd636

Los primeros dos DOI para las versiones v1.0 y v1.1 representan las versiones específicas del software. El último DOI representa todas las versiones del paquete de software, es decir, el concepto del paquete de software y el conjunto de versiones. Por eso también los llamamos DOI de versión y DOI de concepto (técnicamente, ambos son simplemente DOI normales).

Puedes notar que los DOI de versión no incluyen un sufijo como ".v1". Lee más abajo para saber por qué.

¿Qué DOI debo usar en las citas?

Normalmente siempre deberías usar el DOI de la versión específica de tu registro en las citas. Esto es para garantizar que otros investigadores puedan acceder al exacto artefacto de investigación que usaste para reproducibilidad. Por defecto, usamos la versión específica para generar citas.

Puedes usar el DOI de concepto que representa todas las versiones en citas cuando sea deseable citar un artefacto de investigación en evolución, sin ser específico sobre la versión.

¿A dónde redirige el DOI de concepto?

El DOI de concepto redirige a la página de destino de la última versión de tu registro.

Solo quiero cambiar el título de mi carga, ¿aún así obtendré un nuevo DOI?

No, puedes seguir editando los metadatos de tu carga sin crear una nueva versión del registro. Solo deberías crear una nueva versión si deseas actualizar los archivos de tu registro.

¿Por qué los DOI no tienen un sufijo de número de versión como ".v1"?

Incluir información semántica como el número de versión en un DOI es una mala práctica, porque esta información puede cambiar con el tiempo, mientras que los DOI deben permanecer persistentes y no deberían cambiar.

Además, el versionado de DOI es lineal, lo que significa que el número de versión puede no ser el número de versión real del recurso. Tomemos como ejemplo el software, donde es práctica común tener versiones con puntos y hacer nuevos lanzamientos en un orden no lineal (por ejemplo, primero v1.0, luego v1.1, luego v2.0, luego v1.2).

El sufijo de versión tampoco es una funcionalidad del sistema DOI, es decir, agregar .v2 a un DOI no redirigirá a la versión 2 de un recurso para ningún DOI de ningún proveedor. Diferentes proveedores también usan diferentes patrones como por ejemplo .v2, .2, /2.

Lo más importante es que los sufijos de versión no son legibles por máquinas. Un sistema de descubrimiento que entiende DOI, no sabrá que .v1 y .v2 de un DOI son de hecho dos versiones del mismo recurso.

Una mejor solución a este problema es vincular semánticamente dos DOI en los metadatos de un DOI. Esto asegura que los sistemas de descubrimiento tengan una forma legible por máquinas de descubrir que dos DOI son versiones del mismo recurso.

Consulta también Cool DOIs para más información.

¿Duplican todos los archivos por cada nueva versión de un registro?

No, si cambias un archivo README de 10kb en un conjunto de datos de 50GB no duplicamos todo el conjunto de 50GB. InvenioRDM, la plataforma técnica subyacente, maneja eficientemente el almacenamiento de archivos, por lo que solo almacenamos los nuevos 10kb adicionales.
